# Receipt Lab · 回执实验室

一个自建包裹分发台把 `dispatch` 改了名。如何知道哪一个新方法真的把包裹送到了指定通道？本例不靠名称猜：让每个候选处理同样两笔虚构订单，再从独立打开的数据库核对收据。

需要 Python 3.9 或更高版本，无第三方依赖。所有服务都在本机临时目录中运行，不使用网络或账号。

    python3 demo.py
    python3 -I build/parcel-adapter.pyz
    python3 -m unittest -v

第一次执行先建立旧版基线，再枚举新版分发方法。一个候选只返回看似合理的收据号，一个把包裹投到错误通道；两者都会落选。正确的方法还要通过重试：重新打开服务后，同一订单必须返回原收据，不能增加第三次投递。

只有唯一候选通过，才将绑定规则、自建新版服务和复验程序打包。构建器在独立 Python 进程、全新数据目录中执行成品，核对结果后才原子替换本地文件。第二条命令可以随时单独复验。示例只覆盖方法改名且参数不变的情形，不做任意代码发现或调用。
